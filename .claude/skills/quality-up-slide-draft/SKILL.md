# slide-draft.md のクオリティ反復向上

このスキルは `slide-draft.md` のクオリティを **3 サイクル反復** で上げる。

## 入力

- `slide-draft.md` (プロジェクトルートにある原稿)

## 動き方

3 サイクルを順次実行する。各サイクル間でユーザー入力を待つ。

### サイクル 1
1. 下位スキル `quality-up-slide-draft-cycle` を実行
2. 終了時にユーザーへ報告:
    - 適用した主な変更
    - 自動で埋めた `[要確認]`
    - **ユーザー判断必要な `[要確認]` の一覧**
3. ユーザーが `[要確認]` を解消するのを待つ (ユーザーが解消したら明示的に次サイクルへ進むよう指示する)

### サイクル 2
1. 下位スキル `quality-up-slide-draft-cycle` を実行
2. サイクル 1 と同様に報告 → ユーザー解消待ち

### サイクル 3
1. 下位スキル `quality-up-slide-draft-cycle` を実行
2. 最終報告:
    - 3 サイクルの変更まとめ
    - 残っている `[要確認]` (もしあれば)
    - `slide-draft-history.md` に全サイクルの履歴が残っていること

## 重要な原則

- 各サイクルは独立に動く (前のサイクルの結果を踏まえて、また 3 視点で評価する)
- サイクル間で必ずユーザー入力を待つ (`[要確認]` 解消が前提)
- 3 サイクル完了後、追加サイクルが必要かどうかユーザーに確認する
- このスキル自身は「ループ制御 + サイクル間のユーザー報告」が責務。実際の評価・改善は下位スキルに任せる

## 注意

- ユーザーが `[要確認]` を解消しないまま次サイクルに進ませた場合は、解消されていないことを履歴に残した上で進行してよい
- ユーザーが途中で中断指示 (「もう十分」など) を出したら、その時点で最終報告して終了する

## 3 サイクル完了後の最適化 (このスキル群の自己最適化)

3 サイクル反復が完了したら、本スキル (`quality-up-slide-draft`) と下位スキル (`quality-up-slide-draft-cycle`) の両方を見直し、運用で得た改善点を反映する。

- 想定どおりに動かなかった箇所はないか
- サイクル数 (3 回) は適切か
- 3 視点の評価サブエージェントは過不足ないか
- 報告フォーマットや履歴フォーマットは適切か
- 自動で埋められる `[要確認]` の範囲は適切か
- **Claude の判断ハードルを下げる**: 細部の 1 件ずつをユーザーに確認しに行く運用はスキルの価値を下げる。明確な改善方向があるもの (表現磨き、既存方針に従う構造調整、整合性確保、事実誤認の修正など) は Claude が判断して自動適用する。ユーザー判断を仰ぐのは「設計方針が分かれる重要な選択」「ユーザー固有の情報が必要なもの」「影響範囲が大きく後戻りしにくいもの」に絞る。判断の目安: 「これは独断で進めても、後で『なぜそうした?』と聞かれて答えられるか」 — 答えられるなら自動適用

本スキル群は完成形ではない。運用しながら継続的に洗練する前提。
